まち

プライバシーポリシー

更新日: 2026-10-27

1. この方針について

「まち」（以下「本アプリ」といいます。）は、公演の予定、参加履歴および思い出を管理するライブ記録アプリです。オンラインの公演検索・閲覧には EVENTERNOTE の公演・出演者データを使用します。本アプリは利用者による公演・出演者の登録に対応し、任意の EVENTERNOTE アカウント連携により、参加履歴およびフォロー一覧を同期する機能を提供します。基本の記録機能はアカウントへのログインを要しません。本方針は、本アプリの現行バージョンにおけるデータの取扱いを定めるものです。

本アプリは、開発者が運営するデータ中継サーバーまたはアカウント用クラウドサーバーを設置しておらず、広告、第三者の行動分析または追跡 SDK を組み込んでいません。オンライン機能の利用に際しては、当該機能の目的に応じて、EVENTERNOTE、画像配信元および利用者がアクセスする外部サービスに必要なリクエストを送信します。

2. ログインとアカウント操作

メールでのログインでは、入力したメールアドレスまたはユーザー名とパスワードを HTTPS で EVENTERNOTE に直接送信します。本アプリはパスワードを永続保存しません。ログイン維持用の EVENTERNOTE Cookie は iOS キーチェーンに保存します。Safari ログイン助手は、利用者が接続を選んだときに EVENTERNOTE のログイン Cookie のみを端末内の App に渡して検証し、Google や Twitter のパスワード・Cookie は読み取りません。

参加履歴とフォローは端末内に保存します。EVENTERNOTE アカウント接続後の自動同期は標準でオンになり、「データ同期」でオフにできます。アカウントごとの初回は端末とサイトの記録を統合し、以降はサイト上の公演への参加登録・解除、出演者のフォロー・解除を双方向に同期します。本アプリの使用中、フォアグラウンドへの復帰時、記録の変更後に読み取りと同期を行います。オフライン時の変更は端末内に保持し、接続回復後に再試行します。リクエストには公演・出演者の識別情報、検証情報、ログイン Cookie が含まれます。手動のアップロード・ダウンロードによる置換では引き続きプレビューと確認を行います。自作の公演・出演者、検討中、手記、選んだ画像はEVENTERNOTE へアップロードしません。サイトの参加登録を解除すると対応するサイト上のノートも削除される場合があります。

3. 閲覧・先読み・データ同期

閲覧・検索・先読みでは EVENTERNOTE に公演・出演者情報をリクエストし、検索語、選択日、ページのパス、既存のログインセッションを送る場合があります。先読みは表示を速くするため、個別のページを開く前にも行われます。アカウント接続中に自動同期がオンの場合、参加履歴とフォロー一覧を自動取得し、上記のルールに従って端末とサイトを更新します。手動同期でも置換プレビューのために一覧を読み取ります。リモート画像は実際の配信元に要求し、EVENTERNOTE のログイン Cookie は付けません。配信元は IP アドレス、リクエスト時刻、クライアント情報を受け取り、自らの方針に従って処理する場合があります。

AniList の出演者写真や関連リンクを取得する際は、AniList に出演者名を送信します。リクエストには EVENTERNOTE のログイン情報、参加履歴、フォロー一覧、利用者が設定した写真は送信しません。写真の表示位置を調整すると、元画像、切り抜いた画像、表示位置を端末に保存します。

TMDB を有効にすると、出演者名と API 認証情報を TMDB に送り、人物情報と写真の URL を取得します。画像サービスから元画像と正方形プレビューを取得します。認証情報は端末の iOS キーチェーンに保存され、設定から削除できます。他の写真サービス、CSV、EVENTERNOTE 同期には含めません。プレビューと元画像の照合、高画質の切り抜き、キャッシュは端末内で処理します。

YouTube の画像を優先するよう指定された出演者に限り、AniList のプロフィールにあるチャンネルリンクから公開ページと画像を取得し、他のオンライン写真より優先して表示します。リクエスト先は YouTube とその画像配信サービスです。Google のログイン情報、Cookie、他の写真サービスの API 認証情報は使用しません。画像と出典リンクを端末にキャッシュし、トリミングも端末内で行います。

これらの指定された出演者について、AniList に YouTube チャンネルのリンクがない場合、同プロフィールに記載された公式サイトやプロフィールページを読み、出演者名を照合して明記されたチャンネルのリンクを探すことがあります。最大で 2 サイトと各サイト内のプロフィール 1 ページを確認し、名前による YouTube 検索は行いません。ログイン Cookie や API 認証情報は送らず、確認した結果は端末にキャッシュします。

アプリにチャンネルが登録されている出演者は、AniList を経由せず、登録済みの YouTube チャンネルと画像を直接取得します。

出演者の写真選択パネルを開くと、YouTube を含む各サービスから必要に応じてプレビューを取得します。選択した写真の提供元は出演者ごとに端末に保存され、以後の更新にも使用します。

公演の作成・編集画面で TMDB を検索すると、入力した検索語と API 認証情報を TMDB に送信します。選んだ人物の ID・名前・情報源は端末に保存し、出演者ページ、検索、写真の取得に使います。EVENTERNOTE の出演者としてはアップロードしません。

会場の場所を追加する際、検索語を Apple マップに送信します。選んだ場所の名前・住所・座標は端末に保存します。検索結果を使わず住所を直接入力することもできます。外部の地図を開くと、選択した地図サービスに住所または座標を渡します。この機能は端末の現在地を要求しません。

4. 端末内のデータと用途

公演のキャッシュ、サイトのアカウント情報、フォロー一覧、参加履歴を端末に保存し、オフライン表示、予定、足跡の集計、検索候補に使います。自作の公演と出演者、検討中の公演、手記・座席・費用、ローカルの名前と自己紹介、現在および過去のアバター、利用者が選択したポスター、出演者の並び順、ブロック・外観設定も端末内に保存し、本アプリから EVENTERNOTE や開発者へアップロードしません。検索候補をオフにしても参加履歴は削除されません。

iCloud 同期は任意の機能です。初回設定ではオンが初期値となり、利用者が確認します。「データ同期」でオフまたはオンに変更できます。有効な場合、参加・検討中の記録、フォロー、自作の公演・出演者、手記（座席・費用を含む）、ニックネーム・自己紹介、現在および過去のアバター、自分で選んだ公演・出演者の画像と元画像、切り抜き・写真提供元の選択、並び順、ブロック・表示設定、および必要な同期状態を、利用者の Apple Account に対応する CloudKit のプライベートデータベースに保存し、端末間で同期します。初回は既存の記録を統合し、その後は変更・削除を同期します。同じ項目の競合は記録された変更バージョンで処理し、異なる項目は個別に統合します。画像は既存のファイルのまま転送し、同期による再圧縮は行いません。

EVENTERNOTE のパスワード・ログイン Cookie、写真サービスの API 認証情報、法的文書への同意記録、および通常のネットワークキャッシュは、本アプリの iCloud 同期に含めません。iCloud 同期と EVENTERNOTE アカウント同期は別々に管理します。本アプリは Apple の iCloud サービスを使用し、開発者が同期サーバーを運営することはありません。iCloud 同期をオフにすると以後の同期を停止しますが、端末や iCloud に保存済みのデータは削除しません。Apple Account が変わった場合は、本機の記録を新しいアカウントに統合するか再度確認します。iCloud のデータ処理および端末バックアップには、Apple の規約・プライバシーポリシー・システム設定が別途適用されます。

初回利用には本規約とプライバシーポリシーへの明示的な同意が必要です。同意した文書のバージョンと日時は端末内のみに記録し、EVENTERNOTE や開発者へ送信しません。文書のバージョンが更新された場合は再度確認を求めます。同意前に本アプリが EVENTERNOTE のデータ取得を開始することはありません。

5. 写真・共有・外部サービス

アバターやポスターはシステムの写真ピッカーで選択し、選んだ画像だけを取得します。レシートを写真に保存するときは写真の追加権限を求めます。許可しなくても公演の閲覧はできます。本アプリは連絡先、マイク、端末の位置情報の権限を求めません。

CSV、レシート、画像の書き出し・共有では、選択した App やサービスに内容を渡します。共有前に、氏名、予定、座席、費用等の個人情報の有無を利用者が確認する必要があります。地図を開くと会場の検索内容を選択先に渡します。地図の位置情報利用、Safari、外部ログイン、リンク先、共有先のデータ取扱いは各提供元の方針に従います。

出演者ページを開くと、写真を探すために出演者名を AniList の公開 API に送信し、同サービスの画像サーバーから写真を取得する場合があります。EVENTERNOTE のログイン Cookie、アカウント情報、参加履歴は送信しません。出典リンクは出演者ページのその他メニューに表示し、結果と写真は端末にキャッシュします。利用者が選択した出演者の写真はシステムの写真選択と端末内のトリミングを使用し、端末に保存します。

6. 保存と削除

端末内の記録は、該当データまたは App を削除するまで保存します。キャッシュは更新・削除されることがあり、確実なバックアップではありません。手記、過去のアバターの削除やサイトのポスターへの復元は各画面で行えます。ログアウトで本アプリの保存済みログインセッションを削除しますが、手記、検討中の公演、取得済みの記録、Safari のログイン状態は削除しません。

端末内のデータを一括して削除する場合は、ログアウト後に iOS の「App を削除」を選択する必要があります。「App を取り除く」は書類とデータを残します。キーチェーン項目は App 削除後も残る場合があります。共有済みファイル、写真およびシステムバックアップは別途管理する必要があります。端末内の削除だけでは、サイトの参加登録・フォローの解除や EVENTERNOTE アカウントの削除は行われません。

アプリの削除前に、「設定 → 写真サービス → TMDB」に保存された API 認証情報も削除する必要があります。写真キャッシュは通常、再利用のため保持し、写真の更新や削除により変わることがあります。ダウンロードした写真のアーカイブは端末バックアップの対象外です。

iCloud 同期が有効な場合、同期対象の項目をアプリ内で変更・削除すると、同じ Apple Account の他の端末にも反映します。オフラインでの操作は同期再開後に処理します。App の削除や同期の停止では iCloud の記録は削除されず、再インストールして同期を有効にすると再取得できます。本アプリのクラウドデータはシステムの iCloud ストレージ管理から管理できます。他の端末への同期も停止する場合は、先に当該端末で本アプリの iCloud 同期をオフにする必要があります。

7. お問い合わせと方針の変更

開発者は端末内だけにあるデータを遠隔で閲覧・削除できません。本アプリのプライバシーに関する問い合わせは開発者が受け付けます。サイト上のデータやアカウントの訂正・削除に関する請求は EVENTERNOTE が取り扱います。問い合わせにはパスワードやログイン Cookie を含めないものとします。

本方針は現行機能を対象とします。利用目的、送信先、権限の重要な変更時には説明を更新し、法令上必要な同意を事前に取得します。文面を更新しただけで過去のデータを新たな目的に利用しません。適用法令に基づく権利を制限するものではありません。

8. お問い合わせとベータテスト

利用者がメールまたは TestFlight を通じて問い合わせを行った場合、開発者は送信された連絡先、文章、スクリーンショット、添付ファイルを受け取ります。Apple は TestFlight を通じてクラッシュレポート、端末・OS のバージョン、テスト利用情報を提供する場合があります。問い合わせにはパスワード、ログイン Cookie または API キーを含めないものとします。これらは返信、不具合調査、本アプリの改善に使用し、広告には使用しません。

お問い合わせと関連メールは、対応、修正の確認、必要な法的義務のために必要な期間だけ保持します。利用者は、下記メールアドレスを通じて、開発者が保有する問い合わせ情報の確認、訂正または削除を請求できます。Apple、メールサービスなどは各自の方針に従ってデータを取り扱います。TestFlight のテスト情報については Apple の TestFlight プライバシー説明が適用されます。

隐私政策

更新日期: 2026-10-27

1. 适用范围

「まち」（以下简称“本应用”）是一款演出记录应用，用于行程安排、参加记录与回忆整理。在线演出搜索与浏览使用 EVENTERNOTE 的演出及出演者数据。本应用支持自建演出及出演者，并提供可选的 EVENTERNOTE 账号同步功能，用于同步参加记录与关注列表。核心记录功能无需登录账号。本政策说明本应用当前版本的数据处理方式。

本应用未设置由开发者运营的数据中转或云端账号服务器，亦未接入广告、第三方行为分析或用户追踪 SDK。在线功能根据其用途，向 EVENTERNOTE、图片服务及用户主动访问的外部服务发送必要请求。

2. 登录与账号操作

邮箱登录时，输入的邮箱或用户名及密码通过 HTTPS 直接提交给 EVENTERNOTE；本应用 不持久保存密码。用于保持登录的 EVENTERNOTE Cookie 保存在 iOS 钥匙串中。使用 Safari 登录助手时，仅在用户连接账号后将 EVENTERNOTE 的登录 Cookie 交给本机应用 验证，不读取 Google 或 Twitter 的密码或 Cookie。

参加记录及关注保存在本机。连接 EVENTERNOTE 账号后，自动同步默认开启，可在「数据同步」关闭。每个账号首次自动同步合并本机与网站记录，之后双向同步网站演出的参加登记、取消登记，以及出演者的关注与取消关注。本应用在使用期间、重新进入前台及记录变更后自动读取并同步；离线时保留本机变更，恢复连接后重试。请求包含演出或出演者标识、必要校验信息及登录 Cookie。手动上传覆盖、下载覆盖仍需预览并确认。自建演出、自建出演者、考虑参加、手记及自选图片均不上传至 EVENTERNOTE。取消网站参加记录可能同时删除对应的网站笔记。

3. 浏览、预加载与数据同步

浏览、搜索及预加载会向 EVENTERNOTE 请求演出和出演者信息；搜索词、所选日期、页面路径及已有登录会话可能随请求发送。为提高显示速度，预加载可能在相关页面打开前执行。连接账号并开启自动同步时，本应用会自动读取参加记录与关注列表，并按上述同步规则更新本机和网站。手动同步也会读取这些列表以生成覆盖预览。远程图片向其实际托管方请求，不附带本应用 的 EVENTERNOTE 登录 Cookie。接收方可能获得 IP 地址、请求时间及网络客户端信息，并依其政策处理。

查询 AniList 的出演者照片及相关链接时，会向 AniList 发送出演者姓名。请求不附带 EVENTERNOTE 登录信息，也不上传参加记录、关注列表或自定义照片。调整照片取景会将原图、裁切结果和取景位置保存在本机。

启用 TMDB 后，本应用会向 TMDB 发送出演者姓名及用户的 API 凭证，获取人物资料和照片地址，并向其图片服务请求原图及方形预览。API 凭证保存在本机 iOS 钥匙串，可在设置中移除，不发送给其他照片服务，也不包含在 CSV 或 EVENTERNOTE 同步中。小图与原图的取景匹配、高清裁切及缓存均在本机处理。

仅对指定优先使用 YouTube 头像的出演者，本应用会通过 AniList 资料中的频道链接读取公开页面与头像，并优先于其他网络照片显示。请求发送到 YouTube 及其图片服务，不使用 Google 登录、Cookie 或其他照片服务的 API 凭证。头像与来源链接会缓存在本机，取景调整也在本机完成。

对于这些指定出演者，AniList 未提供 YouTube 频道链接时，本应用可读取该资料中列出的官方网站或个人资料页，核对出演者姓名并查找明确列出的频道链接。每次最多查询两个网站及各一个同站资料页，不以姓名搜索 YouTube。此类网页请求不携带登录 Cookie 或 API 凭证，频道查询结果缓存在本机。

对于本应用内置的出演者频道关联，本应用会直接请求已列出的 YouTube 频道及头像，无需先查询 AniList。

打开出演者照片选择面板时，本应用会按需向各照片来源请求预览，包括 YouTube。用户选择的照片来源会按出演者保存在本机；后续更新继续使用该来源。

在新建或编辑演出时使用 TMDB 搜索，会向 TMDB 发送用户输入的搜索词及 API 凭证。选中的人物 ID、姓名和所属来源保存在本机，用于出演者页面、搜索和后续照片查询；不会作为 EVENTERNOTE 出演者上传。

添加会场地图位置时，地点搜索词会发送给 Apple 地图，所选地点名称、地址及坐标保存在本机。直接填写地址不需要地点搜索结果。打开外部地图时，会向所选地图服务传递会场地址或坐标；本功能不请求设备的当前位置。

4. 本机数据与用途

演出缓存、网站账号资料、关注列表及参加记录保存在设备上，用于离线显示、行程、足迹统计和搜索建议。自建演出和出演者、考虑参加、私人手记及座位／开销、本地昵称和签名、头像及历史头像、自选海报、出演者排序、屏蔽和外观偏好也保存在本机，不由本应用 上传给 EVENTERNOTE 或开发者。关闭搜索建议只关闭展示，不会删除参加记录。

iCloud 同步为可选功能，在首次设置页面默认开启，由用户确认；亦可在「数据同步」中关闭或重新开启。开启后，参加与考虑参加记录、关注列表、自建演出及出演者、手记（含座位及开销）、昵称及签名、头像及历史头像、自选演出与出演者图片及原图、取景与照片来源选择、排序、屏蔽及界面偏好，以及必要的同步状态，将保存至用户 Apple 账号对应的 CloudKit 私有数据库，用于在设备间同步。首次开启合并已有记录，后续同步修改与删除；同一项发生冲突时按记录的修改版本处理，不同项目分别合并。图片以现有文件传输，不因同步重新压缩。

1. 適用範圍

「まち」（下稱「本應用程式」）是一款演出記錄應用程式，用於行程安排、參加記錄與回憶整理。網上演出搜尋與瀏覽使用 EVENTERNOTE 的演出及出演者資料。本應用程式支援自建演出及出演者，並提供可選的 EVENTERNOTE 帳戶同步功能，用於同步參加記錄與關注清單。核心記錄功能毋須登入帳戶。本政策說明本應用程式現行版本的資料處理方式。

本應用程式未設置由開發者營運的資料中轉或雲端帳戶伺服器，亦未接入廣告、第三方行為分析或用戶追蹤 SDK。網上功能按其用途，向 EVENTERNOTE、圖片服務及用戶主動存取的外部服務傳送所需請求。

2. 登入與帳戶操作

以電郵登入時，輸入的電郵地址或用戶名稱及密碼會透過 HTTPS 直接傳送給 EVENTERNOTE；本應用程式 不會持久儲存密碼。維持登入所需的 EVENTERNOTE Cookie 儲存在 iOS 鑰匙圈內。使用 Safari 登入助手時，僅在用戶選擇連接帳戶後，將 EVENTERNOTE 的登入 Cookie 交給本機應用程式 驗證，不讀取 Google 或 Twitter 的密碼或 Cookie。

參加紀錄及關注儲存在本機。連接 EVENTERNOTE 帳戶後，自動同步預設開啟，可在「資料同步」關閉。每個帳戶首次自動同步合併本機與網站紀錄，之後雙向同步網站演出的參加登記、取消登記，以及出演者的關注與取消關注。本應用程式在使用期間、重新進入前景及紀錄變更後自動讀取並同步；離線時保留本機變更，恢復連線後重試。請求包含演出或出演者識別資料、所需驗證資訊及登入 Cookie。手動上載覆蓋、下載覆蓋仍需預覽並確認。自建演出、自建出演者、考慮參加、手記及自選圖片均不上載。取消網站參加紀錄可能同時刪除對應的網站筆記。

3. 瀏覽、預先載入及資料同步

瀏覽、搜尋及預先載入會向 EVENTERNOTE 請求演出和出演者資訊；搜尋詞、所選日期、頁面路徑及現有登入工作階段可能隨請求傳送。為提高顯示速度，預先載入可能在相關頁面開啟前執行。連接帳戶並開啟自動同步時，本應用程式會自動讀取參加紀錄與關注清單，並按上述同步規則更新本機和網站。手動同步亦會讀取這些清單以產生覆蓋預覽。遠端圖片向實際託管方請求，不附帶本應用程式 的 EVENTERNOTE 登入 Cookie。接收方可能取得 IP 位址、請求時間及網絡客戶端資訊，並依其政策處理。

查詢 AniList 的出演者相片及相關連結時，會向 AniList 傳送出演者姓名。請求不附帶 EVENTERNOTE 登入資料，也不上載參加紀錄、關注清單或自訂相片。調整相片取景會將原圖、裁切結果及取景位置儲存在本機。

啟用 TMDB 後，本應用程式會向 TMDB 傳送出演者姓名及用戶的 API 憑證，取得人物資料和相片網址，並向其圖片服務請求原圖及正方形預覽。API 憑證儲存在本機 iOS 鑰匙圈，可於設定中移除，不傳送給其他相片服務，也不包含在 CSV 或 EVENTERNOTE 同步中。小圖與原圖的取景配對、高清裁切及快取均在本機處理。

僅對指定優先使用 YouTube 頭像的出演者，本應用程式會透過 AniList 資料中的頻道連結讀取公開頁面與頭像，並優先於其他網上相片顯示。請求傳送至 YouTube 及其圖片服務，不使用 Google 登入、Cookie 或其他相片服務的 API 憑證。頭像與來源連結會快取於本機，取景調整亦在本機完成。

對於這些指定出演者，AniList 未提供 YouTube 頻道連結時，本應用程式可讀取該資料中列出的官方網站或個人資料頁，核對出演者姓名並尋找明確列出的頻道連結。每次最多查詢兩個網站及各一個同站資料頁，不以姓名搜尋 YouTube。這類網頁請求不附帶登入 Cookie 或 API 憑證，頻道查詢結果會快取於本機。

對於本應用程式內置的出演者頻道關聯，本應用程式會直接請求已列出的 YouTube 頻道及頭像，毋須先查詢 AniList。

開啟出演者相片選擇面板時，本應用程式會按需要向各相片來源請求預覽，包括 YouTube。用戶選擇的相片來源會按出演者儲存於本機；之後更新繼續使用該來源。

建立或編輯演出時使用 TMDB 搜尋，會向 TMDB 傳送用戶輸入的搜尋詞及 API 憑證。所選人物的 ID、姓名及資料來源儲存在本機，用於出演者頁面、搜尋及後續照片查詢；不會作為 EVENTERNOTE 出演者上載。

新增會場地圖位置時，地點搜尋詞會傳送給 Apple 地圖，所選地點名稱、地址及座標儲存在本機。直接填寫地址不需要地點搜尋結果。開啟外部地圖時，會向所選地圖服務傳遞會場地址或座標；本功能不要求裝置的目前位置。

4. 本機資料及用途

演出快取、網站帳戶資料、關注清單及參加紀錄儲存在裝置上，用於離線顯示、行程、足跡統計及搜尋建議。自建演出及出演者、考慮參加、私人手記及座位／開支、本機暱稱和個人簡介、頭像及歷史頭像、自選海報、出演者排序、封鎖及外觀偏好亦儲存在本機，不會由本應用程式 上載至 EVENTERNOTE 或開發者。關閉搜尋建議只停止顯示，不會刪除參加紀錄。

iCloud 同步為可選功能，於首次設定頁面預設開啟，由用戶確認；亦可於「資料同步」關閉或重新開啟。開啟後，參加與考慮參加記錄、關注清單、自建演出及出演者、手記（含座位及開支）、暱稱及個人簡介、頭像及歷史頭像、自選演出與出演者圖片及原圖、取景與相片來源選擇、排序、封鎖及介面偏好，以及所需的同步狀態，將儲存至用戶 Apple 帳戶所屬的 CloudKit 私人資料庫，用於裝置間同步。首次開啟合併現有記錄，其後同步修改與刪除；同一項目發生衝突時按記錄的修改版本處理，不同項目分別合併。圖片以現有檔案傳輸，不因同步重新壓縮。

EVENTERNOTE 密碼及登入 Cookie、相片服務 API 憑證、法律文件同意記錄及一般網絡快取不納入本應用程式的 iCloud 同步。iCloud 同步與 EVENTERNOTE 帳戶同步分別控制；本應用程式使用 Apple 提供的 iCloud 服務，不設開發者營運的同步伺服器。關閉 iCloud 同步會停止後續同步，不刪除裝置或 iCloud 已儲存的資料；更換 Apple 帳戶後，須再次確認本機資料是否合併至新帳戶。iCloud 服務的資料處理及裝置備份另受 Apple 的條款、私隱政策及系統設定規範。

首次使用須主動同意本條款及私隱政策。同意的文件版本及時間只記錄於本機，不會上載至 EVENTERNOTE 或開發者；文件版本更新後須重新確認。未同意前，本應用程式不會開始請求 EVENTERNOTE 資料。

5. 相片、分享及外部服務

選擇頭像或海報時使用系統相片選擇器，只取得用戶選取的圖片；將小票儲存至相片圖庫時會要求加入相片權限。拒絕這些選用權限不影響瀏覽演出。本應用程式 不要求聯絡人、咪高峰或裝置定位權限。

匯出 CSV、分享小票或圖片時，內容會交給用戶選擇的 App 或服務；用戶應於分享前確認其中是否包含姓名、行程、座位、開支或其他私人資料。開啟地圖會將會場搜尋內容交給所選地圖服務，其定位及資料處理由該服務管理。Safari、第三方登入、網頁連結及分享服務的資料處理規則由各提供者另行說明。

查看出演者頁面時，本應用程式可將出演者姓名傳送至 AniList 的公開 API 查詢相片，並向其圖片伺服器取得相片。此請求不含 EVENTERNOTE 的登入 Cookie、帳戶資料或參加紀錄。來源連結顯示於出演者頁面的更多選單；結果及圖片會快取於裝置。自訂出演者相片使用系統相片選擇器及本機裁剪，儲存在裝置上。

6. 保存期限及刪除

本機紀錄會保留至用戶刪除相應內容或刪除 App；快取可能更新或清除，不能視為可靠備份。用戶可於相應頁面刪除手記、歷史頭像或還原網站海報。登出會清除本應用程式 已儲存的登入階段，但不會刪除私人手記、考慮參加、已下載紀錄或 Safari 登入狀態。

完整移除本機資料須先登出，再於 iOS 選擇「刪除 App」；只移除 App 而保留文件與資料的選項並不會清空資料。iOS 鑰匙圈項目可能在刪除 App 後保留，因此刪除 本應用程式不能取代登出。外部匯出檔案、相片及系統備份需另行管理。刪除本機資料不會取消網站參加登記、取消關注或刪除 EVENTERNOTE 帳戶；相關操作須透過網站辦理。

刪除 App 前，亦須於「設定 → 相片服務 → TMDB」移除 API 憑證。相片快取通常會保留供再次使用，並可能因相片更新或清除而改變；已下載的相片封存不納入裝置備份。

開啟 iCloud 同步時，在應用程式內對同步內容進行的修改及刪除會傳送至同一 Apple 帳戶的其他裝置；離線操作於恢復同步後處理。刪除 App 或關閉同步不會刪除 iCloud 記錄，重新安裝並開啟同步後可再次下載。可透過系統的 iCloud 儲存空間管理功能管理本應用程式的雲端資料；如需停止繼續同步至其他裝置，應先在相關裝置關閉本應用程式的 iCloud 同步。

Privacy Policy

Updated: 2026-10-27

1. Scope

machi (まち, the “App”) is a live-event record application for planning attendance and maintaining event records and memories. Online event search and browsing use event and performer data from EVENTERNOTE. The App supports user-created events and performers and provides optional EVENTERNOTE account synchronization for attendance records and followed performers. Its core record-keeping features do not require account sign-in. This policy describes data handling in the current version of the App.

The App has no developer-operated data relay or cloud account server and includes no advertising, third-party behavioral analytics, or tracking SDK. Online features send requests necessary for their operation to EVENTERNOTE, image providers, and external services accessed by users.

2. Sign-in and account actions

Email sign-in sends the email address or username and password directly to EVENTERNOTE over HTTPS. The App does not persist the password. EVENTERNOTE cookies used to maintain the login session are stored in the iOS Keychain. When a user connects an account through the Safari helper, the helper transfers only EVENTERNOTE login cookies to the App on the user's device for verification; it does not read Google or Twitter passwords or cookies.

Attendance and follows are saved on the user's device. Automatic sync is on by default after connecting an EVENTERNOTE account and can be turned off in Data Sync. The first automatic sync for each account merges local and website records. Subsequent syncs send and receive additions and removals for attendance at website events and performer follows. The App checks and syncs during use, on returning to the foreground, and after records change. Offline changes remain on the device and are retried after reconnection. Requests include event or performer identifiers, verification data and login cookies. Manual upload and download replacement still require preview and confirmation. Custom events and performers, considering lists, journals and custom images are not uploaded to EVENTERNOTE. Removing website attendance may also delete its website notes.

3. Browsing, preloading and data sync

Browsing, search and preloading request event and performer information from EVENTERNOTE. Requests may include search terms, selected dates, page paths and an existing login session. Preloading may occur before individual pages are opened to improve display speed. With an account connected and automatic sync enabled, the App automatically reads attendance and follow lists and updates local and website records under the rules above. Manual sync also reads these lists to prepare replacement previews. Remote images are requested from their actual hosts without EVENTERNOTE login cookies. Recipients may receive the originating IP address, request time and network client information and process them under their own policies.

Looking up performer photos and related links on AniList sends performer names to AniList. These requests do not include EVENTERNOTE sign-in information, attendance records, follow lists, or custom photos. Adjusting a photo crop saves the original image, cropped image, and crop position on the device.

When TMDB is enabled, the App sends performer names and the user's API credential to TMDB to retrieve person information and photo URLs, then requests originals and square previews from its image service. The credential is stored in the device iOS Keychain and can be removed in Settings. It is not sent to other photo services or included in CSV or EVENTERNOTE sync. Preview matching, high-resolution cropping and caching take place on the user's device.

Only for performers designated to prefer YouTube, the App reads the public channel page and avatar linked from AniList and uses it before other online photos. Requests go to YouTube and its image service without Google sign-in, cookies or credentials from other photo services. Images and source links are cached on the device; crop adjustments also take place locally.

For these designated performers, if AniList does not provide a YouTube channel link, the App may read official websites or profile pages listed in that record, check the performer name and look for an explicitly linked channel. It checks at most two sites and one profile page within each site, without searching YouTube by name. These requests contain no login cookies or API credentials. Channel lookup results are cached on the device.

For performer channels bundled with the App, the listed YouTube channel and avatar are requested directly without first querying AniList.

Opening a performer’s photo picker requests previews from available sources, including YouTube, as needed. The selected photo source is saved on the device for that performer and used for later updates.

Searching TMDB while creating or editing an event sends the submitted search terms and API credential to TMDB. The selected person ID, name, and source are stored on the user's device for performer pages, search, and later photo requests. They are not uploaded as EVENTERNOTE performers.

When adding a venue location, place searches are sent to Apple Maps. The selected place name, address, and coordinates are stored on the user's device. The App also supports direct address entry without selecting a search result. Opening an external map passes the venue address or coordinates to the chosen map service. This feature does not request the device's current location.

4. On-device data and purposes

Event caches, website account details, follows, and attendance records are stored on the user's device for offline display, itinerary display, archive statistics, and search suggestions. Custom events and performers, considering lists, journals including seats and expenses, the local profile name and biography, current and historical avatars, custom posters, performer order, blocks, and appearance preferences also stay on-device and are not uploaded by the App to EVENTERNOTE or the developer. Turning off suggestions hides suggestions; it does not delete attendance history.

iCloud sync is optional. Its switch is initially on in first-run setup, where the user confirms the choice; it can later be turned off or on in Data Sync. When enabled, attendance and considering records, follows, custom events and performers, journals including seats and expenses, profile names and biographies, current and historical avatars, selected event and performer images and originals, crops and photo-source choices, ordering, blocks, display preferences, and necessary sync state are stored in the CloudKit private database associated with the user’s Apple Account for synchronization across devices. Initial synchronization merges existing records; later changes and deletions synchronize. Conflicts within an item use its recorded modification version, while separate items merge independently. Images are transferred as existing files without recompression for sync.

EVENTERNOTE passwords and login cookies, photo-service API credentials, legal-consent records, and ordinary network caches are excluded from the App’s iCloud sync. iCloud sync and EVENTERNOTE account sync are controlled separately. The App uses Apple’s iCloud service without a developer-operated sync server. Turning off iCloud sync stops future synchronization but does not delete data already stored locally or in iCloud. After an Apple Account change, merging local records into the new account requires confirmation. Apple’s terms, privacy policy, and system settings separately govern iCloud data processing and device backups.

First use requires explicit agreement to these terms and the privacy policy. The accepted document revision and time are recorded only on the user's device, not sent to EVENTERNOTE or the developer. A new document revision requires agreement again. The App does not start requesting EVENTERNOTE data before agreement.

5. Photos, sharing and external services

The system photo picker gives the App only images selected by the user for avatars or posters. Saving a receipt to Photos requests permission to add photos. Declining these optional permissions does not prevent browsing events. The App does not request contacts, microphone, or device location access.

CSV exports and shared receipts or images are handed to the destination app or service selected by the user. Users should review the content for names, itineraries, seats, expenses, or other personal information before sharing. Opening a map sends the venue search to the selected map service; that service manages its location use. Safari, external sign-in providers, linked websites, and sharing destinations have their own data practices.

Opening a performer page may send the performer’s name to the public AniList API to find a photo and request that photo from its image server. These requests do not contain EVENTERNOTE login cookies, account details or attendance history. The performer’s More menu links to the source. Results and images are cached on the device. Custom performer photos use the system photo picker and on-device cropping and are stored on the device.

6. Retention and deletion

Local records are retained until the user deletes the relevant content or the App. Caches may be refreshed or evicted and are not a reliable backup. Journals and historical avatars can be deleted, and website posters restored, from their respective screens. Signing out clears the App's saved login session, but leaves journals, considering lists, downloaded records, and Safari sign-in state.

Removal of the App's local data requires signing out and then selecting Delete App in iOS. Offload App keeps documents and data. Keychain items may survive app deletion, so deleting the App is not a substitute for signing out. Exported files, photos, and system backups require separate management. Local deletion does not cancel attendance, unfollow performers, or delete the user's EVENTERNOTE account; those actions are handled through the website.

API credentials should also be removed in Settings → Photo services → TMDB before the App is deleted. Photo caches are normally retained for reuse and may change when photos are updated or removed. The downloaded photo archive is excluded from device backups.

With iCloud sync enabled, in-app changes and deletions of synchronized content propagate to other devices using the same Apple Account; offline operations are processed when synchronization resumes. Deleting the App or turning sync off does not delete iCloud records, which can be downloaded again after reinstalling and enabling sync. The App’s cloud data can be managed through system iCloud storage management. To stop further synchronization from other devices, iCloud sync for the App should first be disabled on those devices.
